낙관적 - 비관적 락: 동시성 제어 전략  
공유 - 배타적 락: 잠금 종류.. 타 트랜잭션 허용하는지.  
<br>

파티셔닝(Partitioning): DB의 큰 테이블 여러 부분으로 나누기  
ex. 1억 거래 내역 => 2024년/2025년/2026년(수평 파티셔닝: 행을 나눔) <=> 수직 파티셔닝  
단일 DB 서버 내부.. 스캐일 업?  
```
SELECT *
FROM transactions
WHERE created_at >= '2026-01-01'
  AND created_at < '2027-01-01';
```
요런 식으로 검색이 가능해짐.  

샤딩(Sharding): 파티셔닝의 한 종류.  
다수의 독립된 물리적 DB 서버.. 스캐일 아웃  
ex. 사용자 데이터 1억건 => user_id%2 = 0 / user_id%2 != 0  
```
shard = user_id % 2 #=> 샤딩 키 예시
```
요런 식으로 접근.

핫 스팟 현상 => 여러 대로 분산했는데 한 곳에 집중되는 현상: 근본적으로 키 재설계 필요성 있음  
Cross-Shard Query => 어떤 요청은 여러 DB를 조회해야 가능한 것: 성능 저하의 대표격  
<br>

**분산 트랜잭션**  
하나의 작업(트랜잭션)이 여러 DB나 서비스에 걸쳐 있을 때 "정합성"을 보장해야 함.  

이체를 한다고 가정해보자:  
```
BEGIN;

UPDATE account
SET balance = balance - 100000
WHERE id = 'A';

UPDATE account
SET balance = balance + 100000
WHERE id = 'B';

COMMIT;
```
만약 두 계좌가 각각 다른 곳에 있다면? => `ROLLBACK`으로 전체 작업 취소 불가함  

1. 2PC(Two-Phase Commit: 2단계 커밋)  
    여러 DB가 커밋될 준비가 되었다고 알림 => 모두 수행(원자성 보장)  
<br>

2. Saga 패턴  
    얘는 접근 방식이 좀 다르다: 로컬 트랜잭션을 단계적 실행 =/=> 단계별 체계적 복구 시스템 구비  
    ```
    정상 처리: 주문 생성 => 결제 완료 => 재고 차감
    복구 처리: 재고 부족 <= 결제 취소 <= 주문 취소
    ```
<br>

수직 확장: 단일 서버 성능 증가 <=> 수평 확장: 서버 여러 대로 증가  
<br>

Replication  
마스터(쓰기 담당.. 주로) =복제=> 슬레이브(읽기 담당)  
CQRS와 연관있음.  
비동기적으로 하다 보니, Replication Lag(복제 지연) 발생 가능  
<br>

**B-Tree** vs **B+ Tree**  
둘 다 B는 Balanced(균형)을 의미한다.  
B+ Tree는 전자의 변형된 형태인데, 리프 노드에만 실제 데이터 저장, 리프 노드 간 연결됨,  
더 많은 자식 노드 가짐: 탐색속도 up  

Buffer Pool(버퍼 풀): DBMS 내부 RAM.. 주로 인덱스 페이지 + 일부 데이터  
변형 LRU를 통해 일부 데이터 캐싱함.  
인덱스로 접근해서 (2차 인덱스) => 최종 데이터는 DB에서 I/O가 발생할 수 있음.  
보통 올릴 때 16KB의 페이지 단위로 올림  

Buffer Pool Pollution => 갑자기 대량 스캔 등을 해서, 이전 데이터가 밀려남.. 좀 꼬이는 거  
<br>

Thundering Herd: 특정 이벤트 후 대량의 작업이 동시에 깨어남  
ex. 대기 중인 스레드 1,000개가 하나의 락이 해제되자 동시에 깨어나기
