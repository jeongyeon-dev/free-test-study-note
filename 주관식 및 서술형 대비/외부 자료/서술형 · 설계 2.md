**문제 07**  
> 동시성 문제이다. 100만원 => 70만원 주문 동시에 × 2  
> 주문 => 외부 브로커 => 결과(비동기 응답)  

여기서 **홀드**라는 개념을 익혀야 한다.  
=> 미리 금액을 확보해서 다른 주문에 사용하지 못하도록 "일시적"으로 묶어둠.  

그냥 "조건부 UPDATE"를 사용하지 않고 홀드를 사용하는 이유?  
조건부로 바로 금액 차감 => 외부 브로커(비동기) => 실패: 돈이 사용된 것으로 기록됨.  
따라서.. 다름과 같은 흐름을 거쳐야 함:  
```
사용자 매수 주문
       ↓
서비스 서버 (주문 접수)
       ↓
주문 금액 홀드
       ↓
외부 브로커로 주문 전달
       ↓
체결 대기 (수초~수시간 가능)
       ↓
체결 → 실제 차감
취소·거부 → 홀드 해제
```
<br>

주문 접수: 멱등성(동일한 주문이 반복해서 브로커 전송 못하도록)  
주문 금액 홀드: 조건부 UPDATE  

체결 확정: 조건부 UPDATE + 트랜잭션 + 멱등성(브로커의 재전송 대비).. 이 필요  
응답 없음: 홀드 상태를 유지(외부 브로커가 멱등성 보장한다면 재시도)  
<br>

*홀드와 체결 차감이 제대로 구현되어 있으면, 접수 순서대로 체결될 필요는 없다*  
*조건부 UPDATE 자체가 베타 락을 사용하므로 직렬화 필요성은 없다*  

-- 베타 락: 해당 트랜젝션만 DB(혹은 행)에 독점적으로 수행
